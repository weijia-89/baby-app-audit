## Dark Pattern Analysis

**Tool:** `scripts/detect-dark-patterns.sh` v1.0 (static APK analysis)  
**Date:** 2026-08-06  
**Scope:** Android apps with decompiled resources (Nurture Lock, Pebbi, Nubo). Baby Buddy excluded - the script targets the Android `res/` layout tree, and Baby Buddy is a Django web app with no Android resources.

**Summary table:**

| App | Pre-checked consent | Hidden consent flow | Deceptive buttons | Obfuscated disclaimer | Pressure tactics | Total | Verdict |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Nurture Lock | none | none | 1 (weak) | none | 1 (false positive) | 2 | inconclusive |
| Pebbi | none | none | 1 (weak) | none | 1 (false positive) | 2 | inconclusive |
| Nubo | none | 1 (false positive) | 1 (weak) | none | 1 (false positive) | 3 | inconclusive |
| Baby Buddy | N/A | N/A | N/A | N/A | N/A | 0 | not applicable |

**Confidence in the findings: low.** All seven patterns the script reported look like false positives or weak heuristic matches once the evidence files are inspected by hand. Each output JSON validates against `results/dark-patterns.schema.json`, but schema-validity does not equal semantic validity. The script's regex heuristics were tuned on unit-test fixtures and misfire on three real-world cases:

1. The pressure-tactic pattern matches the literal substring `timer`. In a baby-tracking app, `Start timer` and `Stop timer` are stopwatch labels. In Danish localizations, `timer` is the word for "hours" (`%1$d timer` = `N hours`). The regex needs word-boundary anchors and language awareness.
2. The deceptive-button-order pattern flags every `Continue` string it finds alongside any localized fragment containing `Decline`. Real `Decline` hits in this corpus were call-notification actions (`call_notification_decline_action`), not consent screens.
3. The hidden-consent-flow pattern flags `layout_width="0dp"` on a WebView as "very small". In a `ConstraintLayout`, `0dp` means "match the constraints", not "hidden". The nubo evidence file is a generic web view activity used for the purchase flow, and contains no privacy or consent text.

Manual cross-check: I grepped every Android resource under `decompiled/{nurture-lock,pebbi,nubo}/resources/res/` for any `android:checked="true"` co-occurring with `consent`, `agree`, `privacy`, `terms`, `opt-in`, or `share data`. Zero hits across all three apps. There is no static evidence of pre-checked consent.

**Recommended next step:** run a dynamic pass against the onboarding and consent flows these apps present at first launch - the existing mitmproxy captures from 2026-08-03 cover the network side but not the UI side. Pair this static script with a UI-automator screenshot pass before publishing a verdict per app.

**Method:** each app's mitmproxy capture (`.mitm`) was converted to HAR via `mitmdump --set hardump`, then decoded into per-app traffic JSON. The comparison script aggregates shared trackers, similar endpoints, data volume, regulatory regime, and shared transmission mechanisms.

**Summary:**

**Shared findings:**

| Dimension | Result |
| --- | --- |
| Shared trackers | none (decode-traffic classifies Firebase/Google endpoints by mechanism, not tracker-domain) |

| Highest-volume app | Pebbi (12 flows, ~7.8 KB total) |

**Per-app decoded traffic:**

- **Nurture Lock** (`results/decode-traffic-nurture-lock.json`): 2 flows, both to `api.revenuecat.com`. Attributed via the `X-Client-Bundle-ID: com.angry.shark.studio.nurturelock` request header. This matches the original dynamic analysis (RevenueCat subscriber API called on every launch). The 0 byte counts reflect `bodySize: -1` in the HAR (unknown size) clamped to 0 on decode.
- **Pebbi** (`results/decode-traffic-pebbi.json`): 12 flows. 8 to `app.pebbi.co` (version-policy endpoint, attributed by host label) plus 4 to `firebaselogging-pa.googleapis.com` (attributed by `packageName` in the request body). No tracker-domain matches because Firebase endpoints are classified by mechanism (`firebase`), not by the tracker-domain list.
- **Nubo** (`results/decode-traffic-nubo.json`): 4 flows. `firebaseinstallations.googleapis.com` (attributed via `X-Android-Package` header), `app-measurement.com` and `infinitedata-pa.googleapis.com` (attributed by package name in body), and `android.apis.google.com/c2dm/register3` (FCM registration, attributed by body). This capture is from the Nubo-only test session.

**Tool limitation surfaced during this run:** `decode-traffic.sh` v2.0's flow-attribution filter only matched flows where the hostname ended with the app name as a suffix (e.g. `com.pebbi.android`). Real-world traffic goes to vendor endpoints (`app.pebbi.co`, `api.revenuecat.com`, `firebaseinstallations.googleapis.com`) where the app identity lives in request headers or JSON bodies, not the hostname. The filter was extended (with regression tests, `tests/test-decode-traffic.sh` Test 16) to also match hostname labels, header values, and JSON body content. A second bug was fixed in the same script: under `set -e`, a schema-validation failure in non-strict mode crashed the script instead of warning - triggered by HAR `bodySize: -1` (unknown size, valid HAR) violating the schema's `minimum: 0`. Fixed by clamping `body_size_bytes` to `max(0, value)` and making the validation command substitution `set -e`-safe.

## Known Limitations

1. **Headless emulation:** I was not able to exercise the app UI interactively. Some data exfiltration paths were not triggered.
2. **No exodus-standalone:** Docker installed but scan not run (linux/amd64 only)
3. **Dark pattern detection heuristics noisy on real APKs:** the script passed its unit tests against clean fixtures but produced 7 false-positive or weak findings on the three real apps (see Dark Pattern Analysis). A dynamic UI pass over the onboarding and consent flows is needed before a per-app verdict becomes publishable.
4. **Nubo static analysis previously not performed:** as of 2026-08-06, Nubo has been decompiled (`decompiled/nubo/`, 10,269 Java files) and scanned for dark patterns. Full tracker fingerprinting still rests on dynamic evidence.
5. **No BLE/NFC/ultrasound scan:** Physical radio checks require real hardware
6. **No objection cert pinning bypass:** Not needed - system certificate installation worked
7. **Cross-app analytics anomaly:** Nubo's analytics payloads contained Pebbi data - possible shared library or test artifact
